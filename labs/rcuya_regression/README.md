# 瑞奇与叮当 3：多人补丁的单人回归

## 背景与证据边界

2026-09-16 的 `3bc0b3f` 新增 `rcuyapatch`，尝试解决多人入口的固定 IOP 地址依赖。
旧代码只检查游戏 ID，在单人启动和每次 IOP 重启时也加载补丁：

- 无条件提前预留 `0x4c900` 处的 321792 字节（314.25 KiB）。
- 所有同尺寸请求都返回该地址，即使上一申请尚未释放。
- `FreeSysMemory` 对该地址直接返回成功，却没有真正释放。

用户报告所有加载链路都可在冷启动单人后按暂停复现，因此不是必须先进入多人才能产生的残留。
以上内存管理缺陷可以从源码和主机测试确认；暂停时具体卡在哪个游戏函数或 RPC，仍需实机日志或断点。

## 修改范围

- `sysLoadElf()` 在 `New_Reset_Iop()` **之前**记录下一 ELF 的模式。
- 只有已登记的 UYA 游戏 ID（美版、欧版、日版）与完整 `I5BOOTN.ELF` 文件名同时匹配，才加载多人 IOP 补丁。
- 文件名接受大小写、路径分隔符和可选的 ISO9660 `;1`，不接受相似文件名。
- EE core 的模式状态跨 IOP 重启保留，但每次 `LoadExecPS2` 换 ELF 都重新计算；返回单人时下一次 IOP 重启清除多人模块和预留块。
- 多人仍在网络／设备模块之前预留固定地址；首次目标申请仅移交一次，移交操作关闭中断保护。
- 移交后保持原始 `FreeSysMemory`，后续定址分配由 sysmem 检查占用状态；重复申请不会别名到仍在使用的缓冲区。
- 其他尺寸、不同显式地址和无效分配模式保持原分配器语义。
- 预留失败时输出 `Kprintf` 诊断并不安装钩子；安装失败时释放预留块。
- 修正短库名比较越界，并在重连导入桩后刷新 I-cache。

本次不修改单人原有的 `RnC3_UYA_patches()`、SMB 的 DEV9／SMAP 隐藏、扇区缓存和 IGR。

范围限制：正常从游戏主入口进入多人是本次目标路径。现有前端把自定义启动文件名同时作为 `GameID`；
直接设置自定义启动为 `I5BOOTN.ELF` 时，原来就不会按 UYA ID 打包补丁，本次也未扩展该路径。
其他修订版、改版或不同入口文件名需先确认，不通过宽泛的字符串匹配猜测。
SMB 隐藏网卡的策略保持不变，本次不宣称增加在线联机支持。

## 主机回归测试

需要 GCC 或兼容编译器与 Python 3，不需要 PS2SDK：

```sh
make -C labs/rcuya_regression test
```

默认使用 AddressSanitizer 和 UndefinedBehaviorSanitizer。编译器不支持时可关闭：

```sh
make -C labs/rcuya_regression clean test SANITIZERS=
```

测试直接包含生产 IOP 补丁实现，链接生产 `ioplib.c` 和 EE 模式识别实现；替代头文件只用于主机测试，
不会参与正常 PS2 构建。EE core 沿用现有 `_strcmp`，不新增 libc 比较函数依赖；主机测试以相等性等价的
libc 包装替代该工具函数。模拟分配器按 256 字节页跟踪地址占用和实际释放。可执行文件写入已忽略的 `tmp/`。

覆盖内容：

1. 三个登记 ID 的单人／多人识别，空值、短文件名、相似文件名和其他游戏排除。
2. 模拟单人 → 多人 → IOP 重启 → 单人，EE 状态与 IOP 预留的生命周期。
3. 一次性移交、未释放时拒绝重叠申请、真实释放及再次申请。
4. 不相关分配和不同显式地址不被改写，无效参数保留原行为。
5. 在移交恢复中断时插入第二个请求，不产生重复所有权。
6. 地址已占用、缺失导出和安装失败的清理。
7. 短库名越界检查、多个导入表重连及缓存刷新。
8. 静态检查模式更新位于 IOP 重启之前，且补丁加载早于设备模块。

这不是完整 EE 系统调用执行、真实多线程、DMA 或游戏测试，不能把通过结果当作实机兼容性证明。

## 实机验收与 A/B

保持同一镜像、存档、设备和配置，对比修改前后；不要同时改兼容模式、网卡隐藏或缓存，避免混淆原因。
先关闭 GSM、PADEMU、金手指和 VMC 等可选项，完成基本对照后再逐项恢复。

| 场景 | 验收点 |
| --- | --- |
| 冷启动主入口 → 单人 | 能进关卡；反复暂停、恢复、打开子菜单；不加载 `rcuyapatch` |
| 单人关卡切换／存读档 | 不出现新的菜单、读盘或存档冻结 |
| 主入口 → 本地多人 | `sysLoadElf` 实际经过 `I5BOOTN.ELF`；固定地址预留成功；能开始和结束对战 |
| 多人内部 IOP 重启／反复进出 | 模式保留，重新预留；没有地址失败诊断；没有重复活跃缓冲区 |
| 多人 → 单人 | 切回单人后不加载补丁；再次暂停正常 |
| USB、MX4SIO、HDD、SMB 等实际使用链路 | 在相同游戏地区版本上重复以上流程，分别记录结果 |

若单人仍冻结，说明暂停的直接原因尚未解决，应继续记录 IOP 最大连续空闲块、分配失败、菜单前后 RPC 状态；
不要仅凭全链路复现就认定一个具体菜单函数已被定位。
若多人没有经过 `sysLoadElf()`，应先抓取实际加载／重启轨迹，再按真实入口调整识别，而不是回到全局强占内存。

## 常驻布局压缩与实机回归

`d05b5bc` 的默认 release 经用户实机验证单人暂停修复有效，但 IGS=1、PADEMU=1 的组合超出常驻边界 108 字节。
`0b88f04` 为节省空间改写了 `syshook/iopmgr` 和状态保存位置；用户报告相同默认 release 再次发生暂停死机。

同一 PS2SDK 下的构建级对照确认：

| 默认 PADEMU=1 构建 | 辅助函数地址 | 写入打包 ELF 的 JAL |
| --- | --- | --- |
| `d05b5bc` | `0x86e1c` | `0x0c021b87` |
| `0b88f04` | `0x86e30` | `0x0c021b8c` |

旧单人补丁直接修改游戏的打包数据，源文件未改不代表最终写入字节未改。
该差异是已确认的回归风险，但没有暂停时断点或解包后的游戏内存，不能声称已经证明具体失败指令。

修正方案：完整恢复 `d05b5bc` 的 EE core 模式判断、独立 BSS 状态、配置布局与调用入口；
空间优化仅共用位于辅助函数之后、默认版不包含的 IGS 五位十进制文本追加序列，
继续使用旧的整数格式化函数，保留输入截断、补零和报告输出，不改变默认编译选项，
不扩大 `ram84`、减小栈或关闭功能。IOP 缓冲区的所有权修复保持不变。

`audit_core_layout.py` 在 CI 中用同一 SDK 重建两个参考提交，不切换工作分支，并校验：

- 四种功能组合的辅助函数地址及编码 JAL 必须与 `d05b5bc` 相同。
- 默认版（IGS=0）的完整 EE core ELF 必须与参考构建的 SHA256 一致，而不只是模式识别单元测试通过。
- 所有新构建仍须通过原链接脚本的常驻边界检查。

这些检查约束构建行为，不替代实机暂停、多人进出以及 IGS 截图回归测试。

截图 DMA 与 GS 寄存器操作不改动；IGS 文本追加的代码合并仍需截图报告实机回归。
