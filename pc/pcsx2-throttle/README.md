# 在 PCSX2 里把读盘速率限到 1 MB/s（模拟 PS2 USB 1.1 的慢链路）

配套报告：`notes/gundam_seed_ce_op_hang_analysis.md`（§0 数据表、§0.11 实机结果、§0.12 下一步）。

## 先说结论

* **PCSX2 没有"限速"选项**。它只有 `fastCDVD`（把读盘时间砍半的加速 hack），没有"放慢"的开关
  （已核对 2.8.x 源码：`EmuConfig` 里跟 CDVD 有关的只有 `fastCDVD` / `CdvdVerboseReads` /
  `CdvdDumpBlocks` / `CdvdPrecache`）。
* **但 PCSX2 本来就带一个光驱速率模型**，它才是"节流"发生的地方：

  ```
  cdvd.ReadTime = PSXCLK / (675 × min(游戏请求的 Speed, 1.6))   ← 每个扇区多少周期
  光驱按这个速率往 16 扇区（32 KB）的读缓冲里补数据，游戏从缓冲里取
  ```

  游戏请求 2x CLV 时，等效速率 = 675 × 1.6 = 1080 扇区/秒 = **2.11 MB/s**。
* 汉化版 OP **开头 1 秒需要 1.932 MB/s**（实测，见报告 §0），比 2.11 小 ⇒ **所以模拟器上它能播过去**。
  USB 1.1 只有 1.0~1.25 MB/s ⇒ 实机上开头就喂不上，1~2 秒内把 0.377 MiB 的预读吃光。
* 想在模拟器里复现实机的"停住"，就得把这个等效速率压到 1.9 MB/s 以下 —— 这就是本目录补丁做的事。

## 补丁：`pcsx2-cdvd-throttle.patch`

对 `pcsx2/CDVD/CDVD.cpp` 加 2 个**环境变量**（不设就等于原版，行为完全不变）：

| 环境变量 | 作用 |
|---|---|
| `PCSX2_CDVD_KBPS=1024` | 光驱等效速率固定为 1024 KB/s（= 1 MB/s），不随游戏请求的速度/盘片位置变化 |
| `PCSX2_CDVD_CMD_US=1500` | （可选）每笔读命令额外加 1.5 ms 固定开销，模拟 USB BOT 的命令往返 |

实现只有三处：一个读环境变量的函数、`cdvdBlockReadTime()` 开头的提前返回、`cdvdStartSeek()`
结尾加的固定开销。启动时会在控制台打一行 `CDVD throttle: 1024 KB/s (...)`。

### 跑起来

```bat
:: cmd.exe
set PCSX2_CDVD_KBPS=1024
set PCSX2_CDVD_CMD_US=1500
pcsx2-qt.exe --iso "汉化版.iso"
```

```powershell
# PowerShell
$env:PCSX2_CDVD_KBPS = "1024"
.\pcsx2-qt.exe --iso "汉化版.iso"
```

（`--iso` 换成你自己的运行方式也行：把 ISO 放哪儿、走菜单启动都可以；只要是从这个 PCSX2 进程启动的。）

### 预测（`python3 rate_check.py` 会重新算一遍）

| 等效链路 | 每秒扇区 | 前 1 秒需求（汉化版 1.93 MB/s） | 前 3 轮需求（2.14 MB/s） | 预测 |
|---|---|---|---|---|
| PCSX2 默认 2x CLV | 1080 | 92% | 102% | 汉化版能播（刚好卡在边界） |
| **USB 1.25 MB/s** | 640 | **155%** | 172% | **汉化版应停、原版正常** |
| **1 MB/s** | 512 | **193%** | 215% | 同上，更确定 |
| 1x CLV（675） | 675 | 147% | 163% | 同上 |

判定口径：

* 汉化版复现停住 + 原版正常 ⇒ **H1 定案**（开头需求 > 链路能力），后续修法都往"降低开头需求"走；
* 两版都正常 ⇒ H1 不成立，回头查"某笔读拿到坏数据/介质问题"（报告 §0.12）；
* 两版都卡 ⇒ 限得太低，把 `PCSX2_CDVD_KBPS` 往上调一档（如 1250、1600）再试。

## 为什么用补丁，而不是"把 ISO 放到慢速 U 盘上"

慢速硬件（USB 1.1 hub / 老 U 盘）也能把宿主读速压下来，5 分钟就能试，但有两个坑：

1. **Windows 会把文件读进系统缓存**：第二次跑同一个 ISO 时，读盘可能几毫秒就返回，限速失效。
   要干净地测，得用 `RAMMap` 清一次 Standby List，或者重启后第一次运行。
2. 宿主读慢，PCSX2 的 **16 扇区读缓冲模型**照旧按 2.11 MB/s 补充 —— 两处节流叠加，等效速率不是你设的那个数。

补丁是直接改"光驱时间"这一个地方，**不受缓存影响、数值精确、可复现**，也方便一次跑 N=1024/1250/1600 三档做对照。

## 局限（先说清楚，免得误读结果）

* PCSX2 的模型是"16 扇区读缓冲 + 按速率补充"，真机 USB 是"按游戏的 8 扇区块读、带命令开销"，
  两者**平均速率**一致，但短时间尺度上的抖动不同；结论（喂不上/喂得上）只依赖平均值，够用。
* 补丁只影响光驱侧的时间，不动 EE/IOP 速度、不动视频解码。
* 只对 ISO/CHD/CSO 等文件源 + 真光盘源都生效（`cdvdBlockReadTime` 是共用的）。
* 不要和 `fastCDVD` 一起开（那个会把时间砍半）。
